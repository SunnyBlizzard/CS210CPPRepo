1. Immediately after construction, topIndex holds a value of 0, as defined by my constructor. This makes isEmpty() return the correct value because isEmpty is checking for topIndex ot be 0 so its already met.
2. my push() method first checks if the stack is full to prevent stack overflow, then our value is inserted into data[] at the index of topIndex, which is then incremented. If we swapped the order of these lines we would end up with no value ever stored in data[0], and we would get a stack overflow trying ot push our 100th value.
3. All 6 of my methods have a big O time complexity that is constant or O(1). None of my methods run nay loops or recursion so they are a constant number of operations ranging form 1-3 on worse case scenarios. For example, pop()'s worse case for time complexity is when isEmpty() returns false. The isEmpty() was 2 operations and pop then does 2 more (topIndex--; and data[topIndex] = -1), for a total of 4 operations. This does not change regardless of n so we are confident this is constant.
4. when push() is called on a full stack, I print "Stack Overflow" and return nothing because the method is void. I chose this because it's the classic error, and I am a fan of StackOverflow (the website). topIndex does NOT change because we aren't modifying the stack, we stopped before that with our isFull() check.
5. pop() has identical (but flipped) functionality to push(). If the stack is empty, there is nothing to pop, so "stack Underflow" is printed. peek() does the same check put instead prints "Stack is Empty" because that felt more appropriate and I wanted a different print message than pop() on an empty stack.
6. To change the stack size you would have to modify the data[] declaration in Stack.h. Personally I would likely include this in the constructor and allow the user to pass in their desired stack size as input for the constructor. This would not change any of our current time complexities as they are all constant and not dependent on n.

You could update the ingoing and outgoing pointers instead of having to iterate through the entire array shifting the data by one.
